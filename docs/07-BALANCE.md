## 7. Победа (по числу фракций, считается по командам)

| Фракций | Domination | Turn limit |
|---|---|---|
| 2 | 60 % | 60 |
| 3–4 | 50 % | 80 |
| 5–6 | 40 % | 100 |
| 7–8 | 35 % | 120 |

Плюс все роутеры во всех случаях. `LateStartBonus` = 3 Compute за позицию
в порядке хода. При командах порог тот же — команда из двух на карте
на 8 должна набрать те же 35 % суммарно.

## 8. Инварианты баланса (проверяются тестами на данных)

- T1 берёт любой `Home`/`IoT` с базовым патчем; T2 — любой `Workstation`
  и неукреплённый `Router`.
- Сервер датацентра (patch 4) без укрепления требует T4; с укреплением +3 —
  недостижим ничем, кроме T5 + native. Вывод: полностью укреплённый
  датацентр берётся только через **аудит/патч-волну** или отрезанием
  и голодом зарядов — это намеренно.
- Полный набор T1 (4 заряда) на старте окупается за ≤ 4 хода.
- Ни один мутатор не даёт > 25 % прироста темпа в первые 10 ходов
  (проверяется авто-партиями).

## 9. Метрики авто-партий (`just balance`)

Прогон N = 200 партий бот-против-бота на случайных сидах, отчёт:

| Метрика | Цель |
|---|---|
| Средняя длина | 35–55 ходов |
| Turn-limit исходы | < 30 % |
| Победы первого ходящего | 45–55 % |
| Победы по мутаторам | ни один набор > 65 % |
| Доход к ходу 10 / 30 | ~10 / ~40 |
| Потерь героев за партию | 2–6 на фракцию |
| Аудитов за партию | 3–10 |
| Партия на 4 фракции (2×2) | длина ≤ 80, побед по turn limit < 40 % |
| Партия на 8 фракций | длина ≤ 120, доигрывается без исключений |

Отчёт — таблица в stdout + JSON в `SHOT_DIR`-подобной папке для сравнения
между правками данных.
