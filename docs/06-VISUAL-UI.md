## 1. Зачем этот документ первым по важности

Главный риск игры — «читаемость невидимого»: драма живёт в радиоэфире.
Сигнальный слой обязан быть визуальным языком с первого дня прототипа.
Если решить красиво — он же становится уникальным лицом игры на скриншотах:
ни у одного выживача такого визуала нет.

## 2. Язык цвета (жёсткое правило: один цвет = одна сила)

| Цвет | Сила | Применение |
|---|---|---|
| **Красный** | Рой | Поля покрытия вышек, конусы дронов, волна скана, маркеры агентов, шкала перепрошивки |
| **Бирюзовый** | Игрок | Ореол сигнатуры, мёртвые зоны как «безопасность», твои устройства (обманки — красным? нет: см. ниже), твоя сторона шкал |
| **Тёплый янтарь** | Люди | Их свет (костры, фонари), конусы зрения, зона лагеря, шкала доверия |

- Исключений нет. На концептах семантика плывёт (большая вышка в `concept_1`
  светит бирюзовым) — в игре так нельзя.
- **Поддельная сигнатура/обманка** — особый случай: излучает «красное» для роя,
  но игроку нужно видеть, что это его инструмент → красное поле с бирюзовой
  обводкой/сердцевиной.
- Свет мира (не принадлежащий силам) — нейтральный, приглушённый, чтобы
  не конкурировать с сигнальным слоем.

## 3. Сигнальный слой (что рисуем на земле)

- **Зоны покрытия** — цветные поля на земле с мягкой границей; плотность
  покрытия читается насыщенностью.
- **Сигнатура игрока** — пульсирующий ореол вокруг робота; радиус и частота
  пульса = текущий уровень излучения. Радиомолчание — ореол гаснет.
- **Сканирующая волна** — физически бегущая по карте стена света с таймером
  предупреждения в логе («Сканирующая волна через 12 сек»).
- **Мёртвая зона** — читаемая «дыра» в полях, при наведении/сканировании
  подписывается.
- **Конусы восприятия людей** — янтарные конусы от глаз/фонарей (они видят
  глазами, не сигналами).

## 4. Состав HUD (по концептам, забрано в дизайн)

- **Центр низа — главная шкала контекста** (0–100%):
  - вне зоны людей: «Заметность в сети»;
  - в зоне людей: «Доверие» становится главной, но заметность **не исчезает** —
    уходит в компактный индикатор рядом (в сцене «чинить насос при лимите
    сигнала 50%» игроку нужны обе).
- **Лево-низ, панель тела:** заряд, целостность, температура, уровень сигнала.
  Слот температуры контекстно заменяется активными режимами
  (радиомолчание, поддельная сигнатура — как в `concept_3`).
- **Право-низ:** мини-карта с полями покрытия + лог событий с таймстампами
  («Дрон потерял цель из виду», «Камера сменила сектор», «Создана мёртвая
  зона») — дешёвый и мощный продавец симуляции.
- **Право-верх, панель угроз:** раздельный статус по силам
  («Сеть машин: СКАНИРУЮТ» / «Люди: НАБЛЮДАЮТ»); в развёрнутом виде — счётчики
  агентов сектора (камеры 12/16, дроны 6/8 …) — заявка на «прореживать можно,
  победить нельзя».
- **Лево-верх:** задачи; критические ограничения — с иконкой предупреждения
  («Не поднимать уровень сигнала выше 50%»).
- **Шкала перепрошивки** — появляется только под вторжением, лево-верх,
  красная, с подписью этапа («Риск сбоя протокола»). Появление самой шкалы —
  уже событие-испуг.
- Глюки UI при перепрошивке — искажения реальных элементов HUD (дёшево и страшно).

## 5. Читаемость и яркость

- Концепты очень тёмные — как настроение отлично, как геймплей опасно.
- Правило прототипа: определить **минимальную яркость геймплея**, при которой
  рельеф и предметы читаются, а сигнальный слой всё ещё выигрышно светится.
  Проверять на срезе, не на скриншотах.
- Тест скриншота: кадр без HUD должен объяснять ситуацию
  (кто где, чьё поле, куда бежать).

## 6. Арт-стиль и пайплайн (принято)

**Стиль: детальный пиксель-арт (hi-bit), весь арт — своими руками.**

Параметры:
- **Тайл изометрии:** ромб 128×64 (2:1) — вдвое плотнее классики,
  хватает на детальный мусор апокалипсиса.
- **Робот игрока:** ~96–128 px высотой; персонажи-люди в том же масштабе.
- **Направления: 4 на старте** (по осям ромба). Ополовинивает стоимость
  анимаций; до 8 можно дорасти точечно после РД.
- **Палитра:** ограниченная палитра мира + три служебных цвета сил (§2).
  Дисциплина: никакой тайл не заезжает в «красный роя».
- Целочисленный зум 2×–3× на 1080p.

**Модули — «бумажная кукла» (решение-страховка столпа «билд = облик»):**
- Корпус и каждый модуль — отдельные слои с общим ригом кадров
  (в Aseprite — слои одного файла, экспорт по слоям).
- Робот в игре = стопка Sprite2D, синхронных по кадру.
- Новый модуль = один слой поверх готовых анимаций корпуса,
  а не перерисовка всех кадров.
- Дисциплина: короткие анимации (idle, walk, работа — 6–8 кадров),
  модули строго по attach-зонам корпуса.

**Инструмент: Aseprite** (тайлмап-режим для тайлсетов, теги анимаций,
reference layer с концептами). Конвейер: CLI-экспорт
(`aseprite -b … --sheet … --data …`) скриптом в `justfile` →
голые PNG + JSON, читаемые своим кодом. Никаких плагинов в Godot.

**Разделение труда пикселя и шейдера:** весь свет сигнального слоя
(ореолы, поля, волна) — НЕ пиксельный, это гладкий шейдерный слой поверх.
Контраст хрустящего пикселя и гладкого света — визуальное лицо игры.

**Аутсорс:** точечно и поздно — Steam-капсула / key art к Next Fest
(мес. 9–10). Конвейер остаётся своим.

**AI-контент:** концепты (`concept_*.png`) — только внутренний референс
и бриф. Игровые ассеты и капсула — рукодельные (Steam требует
декларировать AI-контент; инди-аудитория к нему колючая).

**Арт-тест (недели 6–8 прототипа):** одна улица + робот + вышка
в целевом стиле поверх играющегося greybox. Критерий: сцена без HUD
объясняет ситуацию и «выглядит как скриншот из Steam».
