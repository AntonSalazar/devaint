# ИИ фракции

## 1. Принципы

1. **Играет в ту же игру.** Бот получает тот же `List<Action> Legal(state,
   faction)`, что и UI игрока, и возвращает `Action`. Никаких скрытых
   бонусов, никакого зрения сквозь туман: бот читает `KnownBy[self]`.
2. **Оценка, а не поиск.** Первая версия — жадный оценщик: каждому
   легальному действию — число, берём лучшее, повторяем, пока есть ОД.
   Поиск с заглядыванием (1–2 хода) — только если гейт покажет, что
   жадный бот скучен.
3. **Веса — данные.** `AiProfile { Weights… }` в JSON: агрессия, стелс,
   экономика. Пресеты фракций (`01-WORLD.md`) несут и профиль.
4. **N фракций и команды.** Бот не знает «противника»: цели — узлы всех
   чужих команд, союзные узлы для `Exploit` нелегальны и в оценку не
   попадают. Простое правило «бей лидера»: ценность вражеского узла
   умножается на `1 + wLeader × (доля контроля его команды − моя)`.
   Динамическая дипломатия для бота — после прототипа, вместе с самой
   дипломатией.
5. **Детерминизм.** При равных оценках — детерминированный tie-break
   (по Id узла), чтобы авто-партии воспроизводились от сида.

## 2. Оценка действий героя

Для каждого героя, пока есть ОД:

| Действие | Оценка (эскиз) |
|---|---|
| Exploit(target) | `Value[Type] × (1 + isRouter × wRouter + isServer × wServer + isEnemy × wEnemy) − ChargeCost(tier) − Noise-риск` |
| Move(hex) | `wDist × (уменьшение дистанции до лучшей цели)`; к серверу — если заряды < 50 % |
| Scan | `wScan × (число неизвестных гексов в радиусе)`; первым делом на новом месте |
| Harden | `wHold × (ценность узла) × (враг в радиусе 3)`; серверы и роутеры фронта |
| Lurk | `wStealth × (Noise ≥ 0.6)` — иначе не тратить ОД |

«Лучшая цель» — узел с максимальной оценкой захвата среди известных
в радиусе R; если недостижим — цель движения.

Специальные правила поверх оценки (дёшево, сильно меняет ощущение):
- **Не оставлять героя на узле с `Noise ≥ 0.7`** в конце хода.
- **Не тратить последний заряд T4+** на узел ниже `Server`.
- **Возвращаться на сервер**, если все слоты пусты.

## 3. Политика фракции (покупки)

Простой приоритет в начале хода, пока хватает Compute:

1. Если есть герой с пустыми слотами на сервере — **Compile** эксплойт
   под самую частую ОС среди известных нейтральных узлов рядом с ним,
   тир = минимальный, пробивающий их патч.
2. Если лимит героев не выбран и Compute ≥ `SpawnCost × 1.5` — **Spawn**.
3. Иначе — **Mutate** по приоритету профиля (агрессор — offense,
   стелс — stealth …).
4. Резерв: не опускать Compute ниже стоимости одного T2.

## 4. Сложность

Только через данные, без читов:
- **Бюджет мутаторов:** лёгкий бот — 2 очка, нормальный — 3 (как игрок),
  сложный — 4. Разница видна и честна.
- **Профиль весов:** лёгкий — без спец. правил §2 (шумит, теряет героев).
- Если этого мало — заглядывание на 1 ход для сложного бота.

## 5. Тесты и метрики

- **Партия доигрывается:** два бота от сида доходят до победы или turn limit
  за ≤ 60 ходов, без исключений и зависаний. Тест обязателен в CI.
- **Нет вырождения:** доля partий по turn limit < 30 %; средняя длина
  35–55 ходов.
- **Симметрия:** зеркальные фракции — 45–55 % побед первой (на
  зеркальной карте — ближе к 50 %).
- **Мутаторы не доминируют:** ни один набор на 3 очка не выигрывает
  > 65 % против случайных наборов.
- Всё это — `just balance`: N партий, сводка (`07-BALANCE.md §Метрики`).

## 6. Дорожная карта

- v0 (неделя 3): жадный оценщик + политика покупок + спец. правила.
- v1: заглядывание на 1 ход по «главным» действиям (захват роутера/сервера).
- v2 (после РД): профили-личности, реплики по ситуации.
